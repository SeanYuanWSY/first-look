## 二、轻档输出样例 B：公开工具 / Skill 视角（虚构仓库 `feed2md`）

### 1. 一句话结论
**底子干净（无泄密），但离“陌生人顺手用起来”还差两小步**：离线导出开箱就能试，但安装入口偏繁琐、外链抓取工具没给现成接入指令，新手容易在配环境这一步卡住。

### 2. 陌生人真实上手全流程

1. **安装到自己的 Agent**
   - **现状**：文档要求先 `git clone` 再手动软链到技能目录。
   - **卡点**：缺少 `npx skills add` 这样的一条命令安装入口。

2. **前 1 分钟离线体验（不配账号）**
   - **现状**：有 Node.js 20+ 就能直接跑示例 JSON，立刻在本地生成可预览的 Markdown 摘要。
   - **卡点**：这一步顺畅，但英文 README 首屏图是中文示例，容易误导纯英文用户。

3. **接入真实抓取来源（最容易卡壳的一步）**
   - **现状**：支持 RSS、浏览器抓取、手工 JSON 三选一，不锁死宿主。
   - **卡点**：对外部抓取工具只放了官网链接，**没给复制即装的命令行**，且缺一句“装完第一句话怎么对 AI 说”的示范口令。

4. **真正跑出一轮真实产出**
   - **现状**：输入归一化后渲染链路完整，抓不到全页正文时能退回摘要卡片不报废。
   - **卡点**：动态网站仍依赖用户本机浏览器登录态，需用户自备访问环境。

### 3. 发布前最值得处理的项 & 隐私边界
- **建议发前补齐**：
  1. 增加 `npx skills add <user>/feed2md` 一键安装入口。
  2. 为文档提到的外部工具补一行现成安装命令，并加 2 句示范启动口令。
- **隐私与宣传边界**：隐私与提交历史干净（无密钥、个人邮箱或本机路径）；对外可写“零依赖静态导出 + 多源接入”，**别写**“零配置自动绕过登录抓取”。

## 四、常见反例（禁止这样写）

1. **凭文风猜 AI 写作**
   - 错：“README 排版太工整，疑似 AI 生成。”
   - 对：只报可定位文件与行号（如残留提示词、代理文件或会话注释）；无硬证据不列发现。
2. **把主动公开的 Agent 配置一刀切判成缺陷**
   - 错：“发现 `AGENTS.md`，属于严重 AI 泄露。”
   - 对：中性记为可见事实，对照作者发布意图判定是否移除。
3. **把旧上下文写成无意义否定句**
   - 错：“它不是旧版内部评测平台，也不再支持已删模块 X。”（新访客根本没听过旧版。）
   - 对：只陈述当前拟发布工件呈现的能力与真实前提。
4. **把轻档静态核实写成实跑通过，或把源码实跑泛化到其他渠道**
   - 错：“克隆即可一键跑通（含 Wheel 和 Docker）。”
   - 对：轻档只写静态核实结论；深档把每条实跑绑定到具体渠道和摘要。
5. **在扫描日志或报告中回显敏感原值**
   - 错：“`config.json:12` 发现密钥 `sk-xxxx...` 或邮箱 `foo@bar.com`。”
   - 对：扫描器源头脱敏，只报位置与类型（如“疑似 API Key”“非 noreply 明文邮箱”）。
